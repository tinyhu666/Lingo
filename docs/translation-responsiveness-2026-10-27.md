# 翻译响应优化：2026-10-27

## 基线与验收

基于生产只读日志、滚动最近 7 天、按 operation_id 配对同一操作的 elapsed_ms。客户端到服务端总耗时与模型耗时不能混为一项；以下是修改前数据。

| 阶段 | 样本数 | P50 | P95 |
|---|---:|---:|---:|
| 触发至复制命令完成（含等待组合键松开） | 191 | 248 ms | 1284 ms |
| 复制命令完成至读取到文本 | 170 | 1 ms | 32 ms |
| 客户端翻译请求 | 170 | 838 ms | 1341 ms |
| 请求返回至粘贴命令完成 | 169 | 66 ms | 75 ms |
| 成功的完整翻译流程 | 169 | 1204 ms | 2126 ms |

日志不包含粘贴后恢复剪贴板的 350 ms 锁等待，因此 pipeline succeeded 不等于下一次操作已可开始。

验收：保留原窗口与剪贴板校验；补发复制最多一次且共享 1.5 秒期限；无粘贴操作的失败无需额外等候；重复请求跳过模型；语言/风格/游戏/模式/方向变化不复用旧译文；原有降级与剪贴板互斥测试通过。

## 修复和优化

- **原目标窗口贯穿操作**：旧实现先检查原窗口，再在按键助手内部重新获取当前窗口。窗口若在两者之间变化，助手可能接受新窗口。现在翻译、常用语、选区检测传递同一个 KeyboardTarget，逐次注入仍校验原窗口。
- **Windows 未生效复制的受控恢复**：正常轮询读取不加延迟。150 ms 后仍只有本次探针时，最多补发一次 Ctrl+C，不重发 Ctrl+A；补发前再次检查目标窗口、修饰键和探针，且共享最初的 1.5 秒读取期限。空文本、格式读取错误和已变化的剪贴板不会触发补发。该策略通过模拟回归测试，尚不能断言历史 21 次复制失败都能因此恢复。
- **移除末尾固定等待**：Windows 每段按键序列末尾去掉 20 ms，macOS 去掉 30 ms；按键之间的间隔保留。因此完整复制+粘贴流程理论上减少 40/60 ms 固定等待，实际端到端收益仍需安装新客户端后测量。
- **失败后的再次响应**：尚未尝试粘贴时立即进行条件恢复并释放锁，省去原来的 350 ms 等待；已尝试粘贴（包括部分注入失败）仍保留 350 ms 和互斥锁，防止未消费的粘贴内容被覆盖。
- **组合键超时可诊断**：Windows 错误会附带仍按下的 Ctrl/Alt/Shift/Win。保持松键等待，不强制释放用户按住的键。该原则符合 [Microsoft SendInput 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。
- **重复短句复用**：服务端缓存有效期从 15 秒改为 60 秒，保持最多 256 条和 LRU 淘汰。命中不会续期，降级结果仍不缓存；相同并发请求仍共享一次模型调用。缓存读取直接查目标键，避免每次命中扫描整个表。
- 上一次修复的诊断日志定时清理及过期补报过滤仍包含在工作区改动中。

## 验证

- 102 项 macOS Rust 测试通过；新增覆盖复制一次恢复、持续未复制时不重复注入、空值/读取错误不补发、共享超时预算、窗口切换失败透传。Rust Clippy 与格式检查通过。
- 24 项客户端测试、11 项代理模型/配置/缓存测试、诊断保留回归、翻译 smoke 和 analytics smoke 通过。前端 build、release-config 和 diff 检查通过。
- 本地 smoke 使用 120 ms 的模拟上游：冷请求 124.8 ms，缓存请求 1.6 ms，第二次没有上游请求；上下文变化重新调用模型、并发重复请求仅一次上游调用。这不是线上模型性能提升比例。
- Windows 交叉编译尝试被本机缺少 MSVC C 头文件（ring 构建缺少 assert.h）阻断，不能视为 Windows 编译或游戏实机验证通过。
